# 凡尘篇实现记录

2026-09-21，应用版本 0.3.0，内容版本 0.2.0，规则与存档格式版本 2。

本轮已将设计接入可运行游戏；这里区分已经可玩的功能与尚待制作、试玩的发布要求。00—04 保留为原始设计规格。

## 如何体验

双击项目根目录的 `启动游戏.cmd`，访问 `http://127.0.0.1:5173`。已有同一游戏服务时刷新页面即可。新档进入凡尘篇；原型旧档迁移后仍保持原有桌面和既有人生。要体验新开局，可先导出旧档，再在存档页开启新旅程。

1. 创角在桌面依次经历落笔（姓名）、忆起（出身物件）、自省（天赋）、启程（人物卡确认）；选择进度自动保存。默认独行，出身旧识可选且只在外地通信。
2. 新旧档均使用自由卡牌桌面。打开「行游」，投入自身与「用工告示」。只有开始才占用卡牌与付款，完成才获得工钱和履约信任。
3. 等待计时或点击「等候下一进展」，再「收取成果」。未收取时自身与结果保留在行动中，刷新后仍可领取。预览和摆放不推进世界规则，后台暂停。
4. 同一线索可以配不同动词，补充「谨慎的打算」可以改变做法。自身体卡与地点配行游，抵达后发现当地线索；四条生计均以组合、计时、产出后续卡牌推进。
5. 书院的修法门路投入研习为独立购买注本；投入交游为公开考察；交游补入相识或谨慎的打算为有限指导。之后核验来源并处理责任。
6. 在旧观完成初修准备，研习 MT01/02/03 卡选定方法并理解两次，再修养试行。补入公开注本纠错，复验两次，补入方法要求的地点卡进行应用。疲劳不合适时先回客舍歇息。

## 探索式展开

- 新档最初只有行游与青溪集；看过告示才认识交游、谋生及客舍。完成安顿后发现修养，做完第一份工获得城内其他去处。
- 抵达药铺、作坊或书院引出研习；实际学习和准备引出创作。药铺、听雨亭、书院及核验修法来源分别引出更多去处。所有发现只随实际行动完成，不因预览、摆放或取消产生。
- `mortal.discoveries` 持久化已发现动词和地点，离开不收回。更新前没有此字段的存档保留全部旧入口。创角草稿保存在桌面存档的 `creationDraft`，不提前发放人物资源。
- 游戏内指引仅说明已发现的操作，不预先展示完整修法流程。当前是由内容条件驱动的逐步发现，尚不是任意卡牌组合自动生成新规则的系统。

## 实现范围

| 设计部分 | 当前行为 |
|---|---|
| 独自开局 | 成年、24 文、两日干粮、出身工具；无固定熟人、完整修法或药园权限；背景不封锁其他职业 |
| 十个地点 | 城内与山路分别计时；场所前置实际校验；茶社提供音律专业委托 |
| 四条生计 | CH02 医药、CH04 手艺、CH05 音律、CH06 学问均有学习、难题、成果、后续有预算和需求上限的专业工作 |
| 十条事件链 | CH01—CH10 已配置并接入；每阶段至少两种办法，费用、时长与收益可预览；长叙事被压缩为 2—3 个可执行阶段 |
| 三种渠道与三种方法 | 渠道与方法不绑定，公开注本持续可买；MT02 单独检查辨药；方法不会授予普通职业、通用战力或寿数 |
| 食宿与恢复 | 储粮按日扣除，缺粮时扣 2 文；床位按购买期限顺延，不重复扣租；有限包食宿帮工与低强度工作均可恢复零现金、高疲劳开局 |
| 长期安排 | 规则保留最多 7 次工作的旧安排；桌面当前以手动投入与收取为主，未收取结果会阻断自动安排；不进行离线生产 |
| 人物身份 | 12 类席位、种子与生成序号、唯一人物 ID、相遇 ID、三项背景锚点、固定外观参数、经历、目标、去向与联系途径 |
| 生命周期 | 临时清除、现场 L2、摘要 L1、档案 A 与重要保留分开；行动/合同/邮件/作品/物品/关注均登记保护引用；30 日后可归档；重逢沿用原 ID |
| 关系 | 实际履约才建立关系事实并增加信任；普通相识、同业、有限指导有区别；答应/取消不提前增加信任 |
| 合同与物品 | 独立合同 ID、预留报酬、取消退款、唯一凭据；开工材料真实消耗；旧琴始终属于物主，修理和取消不转移所有权；钱款有账本 |
| 卡牌与操作 | 新旧档共用自由桌面，六动词、动态槽位、拖拽/点击/双击、属性提示、计时与手动收取；线索按已知地点和实际进度出现；人物、工具、钱文、食宿、作品与方法都是卡牌；联系人可分页搜索 |
| 存档 | v1 校验后迁移到 v2；保留旧实体、关系、知识、余额和权限；原 IndexedDB v1 快照不因五份快照轮替被删除；失败不替换当前世界 |
| 可访问性 | 点击槽位/双击/键盘可替代拖拽，桌面可平移缩放，遵循系统减少动画偏好；主要验证 1024/1440 桌面宽度，目前不播放音频；旧版大字设置仍保留在存档字段但未接入桌面控件 |

## 与完整设计的差距

- 24 条短事件目前为按已完成经历/来信触发的轻量分支，记录选择与后续历史。并未全部扩展成原设计要求的天气、债务、借物、插单、监护与伤病事件；其中部分文案采用不创建未实现责任的较小情境。这 24 条不能等同于 24 条完整模拟事件。
- 自由桌面已接入十条链、日常生活、专业工作、方法与相识交谈的卡牌组合；线索仍采用压缩链的步骤，尚未把 AC01—AC30 全部拆成独立可重组配方。地点补有独立线描图标，完整插画与音效仍待制作。
- 已有旅期、来信和同身份重逢；任意约见时段、多方同行采集分配、借琴练习、独立救援流程与全面组织职责尚未开放。师承在本篇是有限指导，不宣称已完成完整师徒系统。
- 十条长链采用可运行压缩版。CH03 的天气窗口、CH04 的四日交期延期、CH07 的动态病程及 CH08 的伤害/失散分支，还需要继续细化；当前都有安全完成或取消退路，但不能按完整动态版本验收。
- 新档没有大型宗门战争、婚育继承或跨域人口模拟，这些本来不属于凡尘篇完整实现范围。
- 尚未完成 6—8 人试玩；4—6 小时主流程、8—10 小时支线不是已经达到的实测结论。当前支持快进的内容更短，不能以空等补足时长。
- M5 的音效、完整独立美术、浏览器最慢帧/P95 帧耗时、长期多设备存储可靠性和人工平衡验收未完成。当前应视为可玩开发版本，而非完整发布验收通过。

## 操作修正

- 租房后可以直接从异地发起休息：城内返程 20 分钟，山路/旧观返程 180 分钟，再休息 360 分钟。预览明确总耗时；铺位需覆盖全程。完成后地点更新为客舍，取消不提前移动或恢复体力，不重复扣租。
- 关闭窗口、Esc 或切换行动会退回未开始的草稿卡牌；真正进行中的投入和待收取结果仍保持占用，通过桌面「卡牌去向」列出名称与状态，点击直达对应行动。

## 验证

- `npm run build`：TypeScript、内容校验、109 项单元/规则/存档测试与生产构建。
- `npm run test:browser`：17 项真实 Edge 浏览器测试，新版自由桌面、点击/真实拖拽、取消、未收取结果跨刷新、地点出行，以及旧版自由桌面、音乐/组织闭环等。
- `npm run test:mortal-performance`：24/32 个现场人物、120 个摘要人物、1000/10000 个档案，实际硬件、存档大小、查询和加载统计保存在 `性能测量.json`。它不代表渲染帧性能或真人试玩。
- 自动规则覆盖四条生计走到首次应用、三渠道、三方法、零钱高疲劳恢复、取消不领款、开工材料不返还、旧琴所有权、读档不重抽、不复活已故角色、100 位即时路人释放、关系实际履约、来信中断快进、归档保护与旧档迁移。

## 工程入口

- `src/content/mortal.ts`：地点、出身、角色席位、十条链、方法、短事件及正式内容校验。
- `src/domain/mortal-model.ts`：严格运行状态 schema，与存档一起校验。
- `src/domain/mortal.ts`：无副作用预览、事务行动、人物生命周期、账本和时间结算。
- `src/domain/engine.ts`：统一 dispatch/advance 调度，新旧模式隔离。
- `src/domain/mortal-cards.ts`：纯卡牌投影、组合解析、占用与结果快照。
- `src/presentation/MortalApp.tsx`：新档创角场景；`App.tsx` 共用自由桌面；`mortal-tabletop.ts` 适配新规则，`MortalPanels.tsx` 提供人物与食宿账册。
- `src/infrastructure/save.ts`：新格式及旧版本内容指纹迁移、快照保留和失败回退。
