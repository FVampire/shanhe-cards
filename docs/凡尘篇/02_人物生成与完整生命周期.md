# 凡尘篇｜人物生成与完整生命周期

版本：设计提案 v0.1；日期：2026-09-21。状态：尚未实现。依据：项目企划 v0.3 与本轮用户要求。

## 1. 人物离开故事，不等于删除身份

人物必须区分三种状态，不能使用一个 active 布尔值代替：

| 维度 | 内容 | 示例 |
|---|---|---|
| 世界状态 | 实际处境、所在地、是否在世 | 在镇上做工、离境、退隐、失踪、死亡 |
| 玩家认知 | 玩家通过什么得知了什么 | 未相识、知道住处、可通信、失联、听闻死讯 |
| 保留等级 | 引擎保留与更新多少内容 | 现场运行、远方摘要、历史档案、清除临时实例 |

一个离境的朋友可以长期保留身份而不逐日模拟；一个死者仍可能影响继承；一个活着的普通路人可以结束出场后释放。

“释放”明确分成四种操作：释放行动占用、卸载运行实例、归档身份、彻底清除临时对象。设计与开发不得混用。

## 2. 人口如何进入世界

### 2.1 三层人口

- 地方人口概况：保存行业、年龄结构、迁入迁出等概况，不创建全镇每个人的完整对象。
- 事件角色席位：事件需要一个合理的人，例如“山脚采药、具备辨药经验、当前有空的成年人”。
- 持续人物身份：发生跨事件约定、关系或重要经历时，保存唯一 personId；每次出场另有 encounterId。

候选顺序：在场的合适人物 → 当地摘要人物 → 有合理行程的外地人物 → 最后才生成新人。忙碌、距离不符、目标冲突的人不能强行复用。复用有事件类别与近期出场限制，避免所有事情都是同一人引发。

将概况中的居民具象化，不增加总人口；释放时撤销具象化占用，不把同一个人重复计入人口。外来旅客有独立流入来源。

### 2.2 来源与接入条件

| 来源 | 接入时机 | 最低背景 | 后续去向 |
|---|---|---|---|
| 本地居民 | 工作、交易、邻里活动 | 居住年限、职业、生活联系 | 继续生活、转业、迁居 |
| 外来旅客 | 商路、游学、投亲、寻医 | 来处、目的、旅费、预计行期 | 下一站、返乡、定居 |
| 出身熟人 | 创角背景或天赋提供，合计最多两人 | 与主角共同经历、最后联系时间 | 约见、通信、寻访 |
| 组织人员 | 拜访、招聘、组织事务 | 所属、岗位、权限、个人目标 | 调任、离职、入队 |
| 历史人物 | 文献、遗物、口述 | 年代、来源可靠性、已知生死 | 调查；符合时间条件才可能活人重逢 |
| 新出生人物 | 后续家庭系统出生事件 | 父母/监护、出生地、出生时点 | 成长；不能直接进入成人岗位 |

生成时点不等于出生时点。每个人保存 origin、enteredWorldAt、entryReason、birthAt 和最少三项背景锚点。不提前展开整棵亲族树，需要时再补充，但不能违反既有年龄、家属、婚姻与年代事实。

## 3. 生成约束

生成流程：事件需求 → 候选筛选 → 复用或新建 → 校验背景与能力 → 绑定生命周期策略 → 保存 → 展示。

模板包含年龄范围、职业经历、技能范围、财富来源、性情、目标池、所属、到访原因、停留时间与退出计划。

- 天资不能替代学习经历；职业成果需有合理来源，道行仍仅按职业等级累计。
- 工作、招募、婚恋分别检查年龄条件；婚恋必须双方成年、自愿，并处理既有承诺。
- 物资具有所有权与来源，不能在多人背包中重复生成同一件稀有物。
- 地点、行程、时间相容；同一个人不能同时在远方旅行和本地做工。
- 已确定背景不重抽；尚未知的细节可以延迟生成，但受已知事实约束。
- 生成序号、随机版本与种子在展示前保存；预览、拖拽和读档不能刷新人选。
- 找不到合法人选时延后事件或改用其他线索，不篡改既有人物。

## 4. 保留等级与状态迁移

| 等级 | 保留内容 | 更新方式 | 示例 |
|---|---|---|---|
| L0 临时出场 | 本次事件需要的外观、台词、即时资源 | 仅事件期间 | 无后续路人、一次性客人 |
| L1 身份摘要 | ID、背景、状态、关键能力、目标、联系途径、压缩经历 | 到期事项或重逢时 | 普通相识、离境行商 |
| L2 现场运行 | L1 加现场行动、库存、日程、当前事件 | 相关调度 | 同行者、当前教学者 |
| P 重要保留 | 永久关系、重要经历与责任 | 在场用 L2，远方用 L1 | 配偶、师徒、核心成员、玩家关注的人 |
| A 经历档案 | 身份、关键历史、最终已知状态、引用 | 默认不主动更新 | 退隐者、久未往来者、已故者 |
| X 临时对象清除 | 只留必要事件结果，无人物实例 | 无 | 无持续引用的 L0 |

P 是保留承诺，独立于模拟精度；开发字段应拆为 retentionClass 与 simulationTier。重要人物不等于永远完整模拟。

```text
人口/旅客来源 → 事件选中 → L0
L0 → 事件结清、无后续 → X
L0 → 约定/关系/跨事件引用 → L1
L1 → 到场或参加行动 → L2
L2 → 离场、空闲、远方 → L1
L1/L2 → 建立重要关系 → 增加 P 保留承诺
L1 → 无待办且长期不相关 → A
A → 合法重逢/寻访 → 原 ID 的 L1/L2
重要关系解除 → 结清责任后取消 P；历史仍保留
死亡 → 结算遗产与未完事项 → 摘要或档案，不可活人重建
```

## 5. 用户提出的三类释放

| 策略 | 触发 | 处理 | 示例 |
|---|---|---|---|
| 用完即释放 | 事件所有结果结算完毕 | 无持续引用的 L0 清除 | 无名客人当面买走草药 |
| 一段时间后释放 | 离场且活跃事务结束 | 先卸载现场，再按保留条件归档 | 行商按期离境，后续无往来 |
| 固定事件后释放 | 指定里程碑成功/失败/取消/过期 | 分账和归还完成后退出现场 | 护送到站、临时雇佣结束、招募会散场 |
| 长期保留 | 家庭、师承、组织、关注成立 | 保留身份，随距离切换精度 | 配偶、弟子、组织负责人 |

普通相识的初始整理参数：离场后 7 游戏日从近期互动区移入联系人；30 日无待办、无关注、无后续种子可转档案。旅客离境依据已公布行程。以上是数据整理参数，不意味着友情到期，更不强制死亡。

姓名不是界限：没报名字但约好明日碰面的船工必须持久化；已报姓名但没有后续的客人可以只留历史摘要。

常驻服务岗位与任职者分离。人物归档不导致药铺凭空停业；换人须有迁居、离职、继任等原因。

## 6. 释放必须先结清引用

| 保护原因 | 负责系统 | 最低保留要求与解除条件 |
|---|---|---|
| 正在行动或旅行 | project/travel | 现场或行程状态；完成/取消/中断后结清 |
| 订单、欠款、托管物 | contract/ledger | 摘要；交付、退款或转移债权后解除 |
| 跨阶段事件角色 | event | 摘要；终结或转交线索后解除 |
| 见面、同行约定 | appointment | 摘要；赴约、取消、违约结算 |
| 在途消息 | message | 收发身份摘要；送达、退信或超时 |
| 家庭、师徒、组织职责 | relationship/organization | 重要身份；关系变更与责任交接 |
| 财产、作者、血缘、师承引用 | ownership/history | 摘要或档案；不能留下悬空 ID |
| 玩家关注 | bookmark | 身份保留；取消关注解除，但不强制人物留在本地 |

引用统一登记 pinReason、ownerId、minimumTier、releaseCondition。不要散落成永远不会解除的布尔值。

释放流程：确定退场原因与去向 → 检查引用 → 事务性结算金钱、装备、关系与承诺 → 取消现场调度/释放占用 → 保存摘要或档案并接续引用 → 无强引用才清除临时对象。

结算留有唯一凭据。保留升级与释放不能并发冲突，避免玩家刚答应同行，人物就被清理。保存恢复必须覆盖事务前后两侧。

## 7. 防止被未完成事件永久锁住

- 有期限委托到期后走明确的退款、违约或延期规则，解除现场占用。
- 无期限调查保留住址、文书、接手者或档案，不保留全天等待的现场 NPC。
- 债务账本独立保存；债权人远行既不免债，也不要求每日模拟他。
- 家庭和组织关系保护身份；不要求所有家人和成员同时占用现场。
- 被忽略的事件可转事后消息；强制暂停不能无限等待没有行动价值的回复。
- 固定事件须有成功、失败、取消、过期、玩家离开五类收尾；不能只有“成功才释放”。
- 不能为清内存而安排集体死亡、突然翻脸或没有预告的财产损失。

## 8. 一生的经历如何保存

永久锚点：出身、重大亲属关系、职业成果、师承、婚姻、迁居、创立组织、重大伤病、死亡。

关系事实：救助、共同冒险、重要失约、债务、承诺兑现、分歧与和解。记录当事人、原因、时点、是否已弥补，不只是好感数字。

普通活动：正常交易、例行练习、日常作息。初始只保留最近 8 条明细，其余聚合为次数、时段、最后一次详情；有效承诺与永久锚点不受这个限额裁剪。

初遇前是受约束背景；初遇后的关键经历是实际结算结果，不能事后改写。并非所有过去都必须逐日模拟，真实感来自一致的因果和记忆。

## 9. 远方生活、衰老和重逢

远方人物只在到期事务、通信、地区更新或重逢时结算年龄、健康阶段、主要职业进展、迁居与承诺。记录 lastSimulatedAt，每个时间跨度只处理一次；跨度很长时按生活阶段处理，不逐分钟补算。

后台事实不自动成为玩家知识。界面应显示“上月来信时住在南埠”，而非实时暴露其全部行踪。失联不等于死亡。

衰老与死亡有独立生命规则，不能作为自动清理手段。凡尘篇实现年龄、调养、伤病和迁居；出生、婚育、继承与完整寿终由后续版本接入同一底座。

归档人物重现需检查：仍在世、行程合理、目标适配、无占用冲突；恢复原 ID 与事实，补算有限变化。后代或继任者必须使用新 ID，并建立真实关系。

### 9.1 生理阶段与社会身份分别推进

| 人生阶段 | 可能发生的生活变化 | 数据与规则要求 |
|---|---|---|
| 出生与幼年 | 被照护、家庭迁居、监护改变 | 有监护责任，不参加成人劳动/婚恋；未进入故事者只作家庭摘要 |
| 成长与求学 | 学艺、建立同辈关系、离乡准备 | 能力来自对应学习；阶段变化以时间与经历为依据 |
| 成年与立业 | 工作、交易、同行、组织加入、自愿亲密关系 | 不自动生成婚姻、职业和财富，必须有实际事件或合理摘要过程 |
| 中年与传授 | 事业、照护家人、教徒、转换目标 | 年龄不强制成为管理者；目标由个人经历决定 |
| 老年或长期修持 | 身体变化、传授、退休、继续事业 | 年龄与身体分开；可靠延年方法有独立来源，不由总道行决定 |
| 离世及身后 | 遗产、继任、悼念、作品流传 | 先处理责任，再归档；身份不参与活人事件匹配 |

阶段名称是内容组织方式，不设人人相同的固定人生脚本；不同种族/体质或传承若在后续加入，必须显式定义其年龄与身体规则。

非死亡退场包括：旅期结束、迁居、返乡、调任、离职、退隐、断交、失联、事件合作结束。每种分别记录 reason、实际去向或未知去向、玩家可知信息、可否联系、可否重逢、未完责任接续者。

岗位继任不能自动复制前任的记忆和感情；新任者只接收合法移交的账本、工作与组织职责。旧友身份与服务岗位保持分离。

## 10. 六个从接入到释放的样例

### A：一次性顾客

集市人口 → 玩家售药时出场 → 看货、付款、拿货 → 没有欠款与约定 → 记录收入 → 清除临时实例。若要求下次留货，答应前升级为持续身份并建立订单。

### B：过路行商

南埠来客 → 商路补给事件抵达 → 告知两日后启程 → 交易/订货 → 行期到达后离境，卸载现场 → 有订单则摘要保护至结清，无待办按时间归档 → 下次商路事件可恢复同一人。打开界面不刷新其行期。

### C：护送同行

本地护送行业 → 应约并签分配规则 → 准备与共同旅行 → 到站、撤回或中途解散 → 分账、归还装备、处理伤势 → 回到原职业 → 有后续关系则摘要保留，否则归档。失败也必须释放队伍占用。

### D：药铺学徒成为宗门成员

药铺人口 → 帮工相识 → 合作、分歧、兑现承诺 → 可信伙伴 → 玩家开药圃后发出邀请 → 比较职责、报酬与求学目标 → 接受后重要保留 → 外派转摘要 → 离职结清 → 成为旧友或疏远相识。加入不是无条件收编，离职不是删除。

### E：共同生活者

活动相识 → 双方自愿往来 → 成年且具备相互倾向 → 商量生计、居所、求道安排 → 自愿结婚 → 记录共同生活责任 → 远行以通信与约定维持 → 分离、解除关系或死亡时处理财产与家庭责任 → 保留关键人生档案。

### F：沈知弦

预设地方人物但开局不认识玩家 → 茶社/听雨亭初遇 → 请教与合奏 → 按原计划赴下游教琴 → 无深入往来转地方摘要；已有师友关系留下通信渠道 → 合理行程后重逢，延续原经历。不会因为一次交谈永久驻留，也不会离场后从世界抹除。

## 11. 人物数量与计算预算

以下是初始压测输入和制作预算，不是已达到的性能指标。

| 项目 | 初值 | 超预算处理 |
|---|---:|---|
| 当前区域现场人物 | 常规 24，额外 8 个事件/返场席位 | 卸载空闲者；非关键新相遇排队；减少普通新人 |
| 单事件新人物 | 通常 0—2，最高 3 | 优先复用、缩减无意义群像 |
| 普通摘要联系人 | 120 软目标 | 无待办、无关注、无后续种子者按久未联系排序归档 |
| 可处理事件展示 | 3—5 | 其余消息归入匣中；重要期限明确显示 |
| 普通活动明细 | 每人最近 8 条 | 压缩为摘要，不裁剪关键事实 |

硬预算用于现场计算。重要人物超过预算时降低模拟频率，不抹掉关系。紧急返场先用预留席位，再卸载空闲者；不能让满员阻止必需救援或人物回家。

摘要和档案按地区/关系索引；只保存实际存在的关系边，不创建人物两两关系矩阵。每 7 游戏日或事件批次后排队整理，单批工作受执行时间预算约束。切图只能在结算安全边界卸载。

长期档案仍需压测。接近实际存储限制时提示备份与容量，不能静默删除重要人物。模板数量有限、背景延迟展开、普通活动聚合共同控制存档增长。

## 12. 数据模块与现有原型的衔接

新增职责：PersonIdentity（身份来源与永久背景）、PersonSummary（生活摘要）、PersonRuntime（现场实例）、PlayerKnowledge（玩家认知）、RelationshipEdge（关系）、LifecyclePolicy（释放策略）、ReferenceRegistry（保护引用）、PersonArchive（经历档案）。

当前 world.ts 固定创建四个人，people.ts 与 events.ts 按固定 ID 处理人物；Entity 的 active、willing 不能承担完整生命周期。可复用现有唯一占用、事务凭据、存档与确定性随机，但人物生成、引用登记、摘要恢复都需要开发。

旧档迁移保留现有人物 ID、已学知识、物品、关系与组织权限；新开局才采用独自进入规则。迁移失败保留原档，不原地覆盖。

## 13. 验收

1. 一百次结清的临时顾客事件不会产生一百个常驻 AI。
2. 路人产生预约后，关事件、切图、读档均能找回同一个人。
3. 同一人不能同时在远方旅行和本地做工；无候选时有延期/替代方案。
4. 归档不清除订单、债务、邮件和托管物；事务结束后可正常降级。
5. 护送成功、失败、取消、过期、中途离开均能结清并释放占用。
6. 配偶、师徒、组织成员远方摘要化后关系与责任保留。
7. 旧友重逢保留原 ID、技能、重大记忆；死亡人物不能复活式重建。
8. 死亡后遗产、作者、血缘、师承引用仍有效。
9. 玩家认知不泄露未知事实，最后所知与世界真相分开。
10. 查看、读档、切图不重复抽取变故，不重置旅期。
11. 无限期调查不永久钉住现场角色；忽略支线仍能推进。
12. 满载减少普通新相遇，不删除重要身份；玩家关注不等于人物瞬移。
13. 释放事务前后保存恢复，金钱、装备、引用、行程、关系一致。
