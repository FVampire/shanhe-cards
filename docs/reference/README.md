## 1. 技术结论

当前企划可以采用网页实现。首版建议面向桌面浏览器，使用 **TypeScript + React + Vite + IndexedDB**。二维卡牌、文字事件、有限区域模拟和小型宗门经营是本方案的设计范围。

游戏采用本地单机规则，没有必需的业务后端。构建结果可以静态部署；Vite的静态部署方式见[官方文档](https://vite.dev/guide/static-deploy)。云存档、账号、联网交易与多人模式另行设计。

网页是当前推荐工程方案。用户尚未确认具体依赖版本，建项时选择彼此兼容的稳定版本并提交锁文件。本交付不安装依赖、不部署网站。

## 3. 开发必须保留的规则

| 编号 | 不变量 | 主要落实位置 |
|---|---|---|
| R01 | 道行等于已获得职业等级之和，晋升一级增加一点 | 职业模型、晋升事务 |
| R02 | 道行只直接影响特殊道具生效概率、趋吉避凶概率 | 专用判定服务、配置编译检查 |
| R03 | 道行不直接增加普通攻防、寿命、专业能力，不作通用门槛 | 规则上下文与依赖检查 |
| R04 | 一个角色同一时间只执行一项主要行动 | 角色占用与调度 |
| R05 | 一份资源不能被重复占用、重复消费或重复发奖 | 资源预留、事务、结算凭据 |
| R06 | 卡牌是对象的显示入口，复制显示不复制对象 | 对象ID、界面投影 |
| R07 | 相同未变化事件的预感不会因拖拽、开关面板、读档而重抽 | 稳定判定键、存档与随机服务 |
| R08 | 事实、人物知情、公开评价分别记录 | 事件、情报、关系模型 |
| R09 | 音乐与学问拥有不依赖战斗胜利的完整内容 | 内容样例、切片验收 |
| R10 | 委托必须有人员、权限、资源和时间，不凭空产生收益 | 组织模型与行动统一调度 |

## 4. 首个开发闭环

读取预设人物 → 组合人物、琴、谱本与老师 → 完成练习和合奏 → 获得具体技艺进展与关系变化 → 接触有期限的演出邀约 → 获得收入和作品记录 → 保存后继续。

在此基础上加入专业晋升、养生与延年探索、小型组织委托；用独立场景验证特殊道具抵抗、避凶与趋吉。战斗不作为上述闭环的必经终点。

## 6. 网页边界

浏览器后台页会限制计时和刷新，因此默认切到后台自动暂停，不按离开网页的现实时间补算世界进度。[Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)

本地存档使用IndexedDB，并提供手动导出和导入。浏览器存储存在配额与清理机制，持久存储申请也不代替备份；存档界面明确显示保存状态与导出入口。[存储配额与清理说明](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)

首版不承诺关闭网页后继续模拟，也不承诺首次加载前即可离线启动。离线安装、手机触控优化和桌面封装属于后续评估项。
