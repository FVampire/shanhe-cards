# 05｜开发任务与验收

基线：企划v0.3；技术文档v0.1。本节是实施计划与验收契约，当前没有游戏代码或实际性能测量。

## 1. 建项前决策

| 项目 | 当前建议 | 最迟决定时间 |
|---|---|---|
| 平台 | 桌面网页优先，以Chrome/Edge为首批验收环境，Firefox补充检查 | M0 |
| 工程 | TypeScript、React、Vite、IndexedDB | M0锁定兼容版本与包管理器 |
| 游戏时间 | 整数游戏分钟、可暂停、后台不补算 | M0 |
| 随机实现 | keyed-v1语义键、固定SHA-256适配器与拒绝采样 | M0补全算法细节和跨环境测试向量 |
| 内容结构 | JSON配置、运行时类型检查、构建前语义检查 | M0 |
| 存档 | 版本化快照、导入导出、单槽单写入者 | M1 |
| 战斗 | 有限阶段遭遇，复用行动与特殊效果服务 | M4前完成具体玩法评审 |
| 寿终与继承 | 尚未决定；先实现年龄、健康、延年方法与风险事件 | 完整人生版本前 |

上述选择不要求现在搭建服务器。网页发布为独立任务，开发阶段只需本地服务与浏览器。

## 2. M0：最小规则与内容工具

实施任务：

- 创建工程、类型检查与最小测试入口，提交依赖锁文件。
- 实现定义ID、实体ID、整数时间和概率值的运行时验证。
- 实现内容加载、引用检查、操作白名单与道行访问限制。
- 定义固定随机算法、稳定键编码和已知向量，避免同档在不同浏览器出现不同结果。
- 实现样例fixture工厂，明确缺省字段与测试专用内容不能进入正式存档。

验收：内容样例通过结构与引用检查；拼错技能ID、把道行写进普通条件、用未知操作或负数材料均被明确拒绝。道行公式的单调性、边界与示例数值正确。

## 3. M1：桌面、行动与保存

实施任务：

- 卡牌展示、拖拽候选、点击替代操作、开始前预览。
- 单一命令入口、版本检查、资源预留与原子结算。
- 游戏时间、到期队列、暂停原因集合与后台暂停。
- 行动开始、结束、取消、中断和结算凭据。
- IndexedDB保存、导出导入、备份恢复和同槽写锁。

验收：两名人物共同练习时均被占用；同一把琴不能同时用于两个项目；整理卡牌不消耗资源；重复完成命令不能重复增加技艺。保存后刷新可以恢复行动剩余时间和所有占用。

## 4. M2：非战斗人生切片

实施任务：

- 完成音律学习、合奏、创作、邀约、演出合同与支付。
- 接入具体知识、心得、关系、意愿和职业晋升。
- 完成一个宗门应聘入口、一个散修师承入口与独行求学入口。
- 加入一次可理解的健康或延年选择，其结果来自具体方法。

验收：玩家能在没有战斗胜利和战斗加成的情况下取得作品、收入、关系与专业成长。两次合奏不能直接自动晋升，完成明确的专业条件后提交晋升才增加一级职业与一点道行。

演出报酬必须来自实际合同与资金来源，不能在收到邀约时提前发钱。拒绝或错过邀约有合理后续，不能导致所有生活路线中断。

## 5. M3：小组织与委托

实施任务：

- 成员、职位、权限、意愿和代理关系。
- 小型药园或工坊、库存、预算、生产周期。
- 负责人按权限创建普通子项目，复用相同资源规则。
- 缺料、拒绝工作、设施损坏、负责人不可用等异常事件。

验收：闭关前安排代理后组织能按已授权规则运行；没有代理时不能把闭关负责人当作免费劳动力。缺料不会继续生成产物，重复异常会合并上报。独行者仍可以租用设施或购买产品推进自己的目标。

## 6. M4：道行、危险与后果

实施任务：

- 实现普通伤害和附带特殊效果分别结算。
- 实现真实情境、接触范围、预感缓存和有限信息提示。
- 接入邪道材料来源、痕迹、调查、消息传播与对应人物反应。
- 实现少量遭遇、撤离、协商与雇佣援助。

验收：高道行提高特殊抵抗与祸福窗口概率，其余无关领域不获得加成。秘密事实不直接触发全世界仇恨；预感失败不等于系统保证安全。

## 7. M5：整合与发布准备

实施任务：完善引导、内容覆盖、存档迁移、错误恢复、桌面整理和性能测试；校验全部正式内容不引用测试物品。

构建链建议依次执行：类型检查 → 内容校验 → 领域与场景测试 → 静态构建 → 浏览器关键流程。普通文案修改只运行相关校验；规则、存档或资源结算修改需要对应回归。

发布前锁定规则、内容与存档版本。构建产物采用带内容指纹的资源名，先完成新版本资源上传再切换入口；运行中的会话不热替换规则或内容包。首版不引入自动更新的Service Worker，避免额外的缓存版本一致性问题。

公开部署、域名与账号服务均需独立安排，不包含在本次文档交付中。

## 8. 自动化测试矩阵

| ID | 测试情境 | 必须成立的结果 |
|---|---|---|
| T01 | 同一人物从两个界面提交行动 | 只允许一个主要行动开始 |
| T02 | 两项目同时预留最后一份材料 | 一个成功，另一个无副作用失败 |
| T03 | 预览后材料被其他项目占用 | 提交重新验证并返回明确原因 |
| T04 | 相同命令重发或完成回调重复 | 不重复扣料或发奖 |
| T05 | 同一职业一级晋升重复提交 | 等级与道行只增加一次 |
| T06 | 有知识文本但未理解或未实践 | 按具体前置拒绝，不能直接掌握专业本领 |
| T07 | 混合伤害法器遇到不同道行目标 | 普通伤害规则不变，只有特殊生效概率改变 |
| T08 | 给普通治疗错误配置道行resolver | 内容校验拒绝或明确要求重新定义为特殊效果 |
| T09 | 同一情境反复开面板、拖拽、重建相同计划 | 不生成新的预感抽签 |
| T10 | 同档同选择分别在不同浏览器运行 | 稳定键、抽样与结果一致 |
| T11 | 新增一个不相关随机检定 | 不改变原事件或物理命中的既有抽样 |
| T12 | 到期瞬间完成带期限的任务 | 按半开区间与phase顺序一致处理 |
| T13 | 一次大步推进与多个小步推进 | 业务结果、年龄余数和资源数量一致 |
| T14 | 保存运行中的项目后重新载入 | 剩余时间、预留、队列与回执一致 |
| T15 | 保存失败、配额不足或快照损坏 | 旧档可恢复，不显示虚假的保存成功 |
| T16 | 两个标签页打开同一存档 | 最多一个可写会话；旧版本不能覆盖新档 |
| T17 | 委托负责人失能、离职或权限撤销 | 后续周期停止或转交，不能继续越权执行 |
| T18 | 存在秘密恶行而无人知晓 | 未知情NPC不直接获知事实 |
| T19 | 被后台暂停后关闭事件面板 | 仍保持后台暂停原因，不恢复模拟 |
| T20 | 从旧版迁移失败 | 保留原档，当前世界不被部分替换 |

## 9. 道行专项测试

概率单元测试对道行D和其他参数分别输入，不修改真实人物中不存在的独立dao字段。集成测试通过不同已获得职业记录构造道行差异，保持当前被检验的普通战斗、药物与技能输入相同。

必须检查：特殊概率随D不增，预感概率随D不减；公式结果在边界内；强度增大不会降低该道具生效概率；相同sampledPpm下结果与阈值比较一致。

使用固定随机样本验证确定性，再用足量独立语义键做分布检查。分布检查采用预设统计容差，不把随机结果恰好等于理论百分比作为通过条件。

普通规则依赖检查与配置拒绝测试同样必要，不能只证明两条公式算对。

## 10. 试玩与性能预算

| 场景 | 初始验收目标，待指定设备实测 |
|---|---|
| 桌面操作 | 约150张可见卡牌，拖拽与展开面板无明显卡顿 |
| 世界数据 | 约200个活动人物、2,000个物品实例、100个并行项目的压力场景 |
| 帧表现 | 普通桌面交互目标接近60fps；记录长帧与原因，不视为已保证 |
| 规则推进 | 分批计算，单次占用主线程预算以不阻塞交互为准，初值约4ms |
| 快照 | 不含图片音频的代表性存档，保存期间不冻结操作；写入时间单独记录 |
| 内容规模 | 覆盖企划首版的80—120种卡牌模板，并测试收纳与筛选 |

以上是测试负载与目标，不能从技术选型直接推断达标。记录设备、浏览器、分辨率、数据规模与统计方法，再决定是否使用Worker或更换桌面渲染方式。

试玩必须观察：玩家是否理解人物差异、是否愿意学琴与访友、能否找到生计、是否理解长生困难、是否知道为什么某次事件发生。仅达到帧率不能证明玩法成立。

## 11. 已知待决项

1. 游戏时间与现实时间的比例，以及日历长度。
2. 各项属性、天资、职业与专业技能的数值范围。
3. 具体境界名称、各传承突破方法和完整寿终规则。
4. 战斗阶段与玩家干预频率。
5. 音乐、养生、炼丹等首批内容的具体晋升条件与成本。
6. 在已确认两项作用内，预感触发频率和具体提示表现。
7. 技术依赖版本、随机适配器细节、正式内容schema与基准设备。

这些项应在对应阶段解决；不阻止先实现卡牌组合、事务、整数时间、配置载入、存档与音乐切片。不得用临时实现默默引入道行的第三种作用。
